# Motion mechanisms with a job

Use these as choices, not a list of effects to fit into every film. The difference between a scene and decoration is whether the mechanism changes what the viewer understands.

| Mechanism | Narrative use | What makes it fail |
| --- | --- | --- |
| Recognizable lockup becoming a sentence | Immediate recognition, then a precise analogy | Logo without wordmark; tiny introductory word; long pause after the sentence |
| One word carried between framings | Explain the category without resetting the scene | Font/weight/baseline/color changes accidentally during the handoff |
| Pullback from detail to system | Start with one understood object, reveal how it connects | Showing the complete diagram first and then aimlessly zooming |
| Macro dive into a control | Make the decisive action unmistakable on mobile | Unmotivated zoom into a large blank panel; cursor missing its target |
| Document → traveling token → document | Show one record routed through a workflow | Losing record identity or showing an unrelated result screen |
| Camera following a drawn route | Explain branching and approval order | Whole flow permanently centered under a title; line draws while camera idles |
| Exploded product assembly | Make manufacturing tangible and connect to BOM/components | A random 3D prop unrelated to the business, or a long beauty shot |
| Layered native UI planes | Reveal connected modules while preserving their identities | Every panel has equal scale/weight; unreadable steep tilt during the hold |
| Foreground pass / parallax | Travel through a software world with spatial depth | Decorative objects covering the active field or text before it is read |
| Overscan / giant cropped type | Add scale after the information is understood | Cropping current essential content, URL, logo or controls |
| Cursor click and state mutation | Make cause and consequence visible | Cursor movement with no click or no change; stale native badge |
| Contrast inversion | Punctuate a result using the same geometry | Unrelated field change behind unrelated text |
| Control/object-driven wipe | Let action generate the next scene | A generic sweep added only to hide a disconnected layout |
| Smooth dissolve | Replace one argument with another cleanly | Using it between every product step or allowing a white flash |
| Curve → rule → full field | Connect time/comparison to offer and close | A line extending asymmetrically at rest; a copied headline jumping at the boundary |
| Deliberate stillness | Let an outcome land before departure | A completed scene lingering because its duration was assigned arbitrarily |

## Contrast without repetition

Vary several dimensions across a passage: macro versus wide, frontal versus oblique, dense versus isolated, light versus ink, slow anticipation versus faster travel. Keep the primary subject or purpose stable through each change. More variety does not mean every cut needs a unique transition plugin.

Avoid a rigid “one change per second” timer. Plan information gain: the input is entered, the import resolves, a relevant item is selected, a form becomes useful, an approval becomes a state change. Motion may briefly rest when comprehension needs it.

## Concrete redesign example

Weak: “Building workflows” in the top left, a complete four-node diagram below, a cursor tracing each node, then a card saying Done.

Better: the current work order fills the camera; pull back to reveal the route leaving its edge. The order contracts into a recognizable token. Travel with it to the branch and manager action menu, momentarily show the alternate return path, and advance into Approve. The cursor click causes the visual confirmation. Pull back to the same native work order marked Approved, with related inventory and production documents at secondary depths. The typography is transient, and the viewport need not show the entire graph at once.

Transfer the logic, not the furniture: for purchasing use a requisition, vendor quote and purchase order; for sales use a lead, opportunity and quote; for accounting use an invoice, reconciliation and posted ledger consequence. Verify the product actually supports the depicted relationship.

## Hook timing example

The accepted launch showed Lovable's mark and wordmark immediately, settled their initial movement quickly, assembled the full comparison, then carried ERP into a module reveal. The key principle is **recognition → qualification → demonstration**. Exact sub-second timings from that film are implementation examples, not a mandatory timing grid.

## Comparison and closing example

Center the complete traditional-implementation statement, move into a visual plan, follow its extent to a recognizable estimate, then dissolve to the Crator time claim. A compressed implementation track leads the camera into a trial invitation. Its line retracts to a balanced width and expands into the dark closing field while the headline stays precisely registered. The real Crator lockup joins it; a smaller URL completes the phrase. Every transition has a source object and a destination purpose.
