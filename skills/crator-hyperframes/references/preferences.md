# What the iteration taught us

Recorded from Yajat's Crator launch-video session, 8–9 September 2026. The final accepted source is v42. These are defaults for future direction, not instructions to reproduce the same film.

## Stable preferences and their reasons

| Feedback pattern | Underlying issue | Better response |
| --- | --- | --- |
| “It's a PPT … an open canvas” | Persistent headline, framed visual and repeated layout resets | Stage a world larger than the viewport; follow subjects and consequences through it |
| “Same animation every time there is progress” | The feature list determines the edit instead of a business story | Import an item, configure that item, route its order, return the changed record; use distinct mechanisms |
| “Not enough visual interest” | Entry finishes early; little changes except a bottom status | Vary scale, depth, density and focal subject; add meaningful operations rather than more labels |
| “Zoomed-in ERP screens aren't working” | Random enlargement removes context and distorts proportions | Orient with a useful UI frame, focus a meaningful target, return to its consequence |
| “Use ERPNext primitives” | Generic UI doesn't establish that real ERP software exists | Native titles, tables, tabs, fields, badges and valid state/action relationships |
| “The message input is way too small” | Desktop-scale UI unreadable in a feed | Magnify the relevant composer coherently, with proportional controls and concise text |
| “0/3 … making changes … there twice” | Presentation scaffolding and redundant explanation | One transient work label plus visible work; no permanent chapter counter |
| “More 3D, more assets” | Empty layouts with code-drawn boxes | Use business objects, depth, shadows, occlusion and layered product planes with narrative purpose |
| “Purple looks weird coming from the existing background” | Background change breaks an otherwise continuous thought | Maintain the field or create a visible transition through an object or inversion |
| “Orange isn't used enough … more important to be visually interesting” | Overcorrection toward neutral brand restraint | Restore purposeful color and contrast at important actions; judge the sequence as a whole |
| “All the same speed … a few are abrupt” | Variety reduced to equally timed camera presets, or overcorrected to hard cuts | Different anticipation/travel/settle durations with smooth velocity where continuity demands it |
| “Composition … hierarchy … off” | Competing blocks and ungrouped supporting information | Measure the whole group, reduce redundant hierarchy, align motifs with the headline |

## Choices that evolved

- **Orbit:** initially requested floating modules, then a double ring felt awkward, then the single ring was unnecessary. Keep the expressive module choreography if useful; do not preserve an ellipse just because an early request mentioned a planet.
- **Color:** violet/green combinations and abrupt purple fields were rejected. Some pastels worked in icon faces and product phases. Bright green was rejected for the offer. This is context-dependent contrast judgment, not a ban on purple or green in all future films.
- **Type:** indiscriminate bold felt generic; later the recognition hook needed stronger presence. Scale and context decide emphasis. Neither “all regular” nor “all bold” captures the preference.
- **Camera:** asked for more dramatic moves, then objected to linear speed and abruptness. Dramatic spatial range and smooth timing are compatible.
- **Pacing:** the early hook lingered after delivering its information. The eventual order made recognition immediate, then completed the analogy and moved onward. A later bill hold lost 0.5 seconds without speeding its dissolve.
- **Ending:** Book a demo changed to a free-trial invitation; the fixed monthly offer was removed for geography-specific pricing. The ending became one continuous invitation with the URL attached beneath it.

## Defaults to reconfirm only when relevant

- Faceless motion graphics for launch/product films; no presenter footage unless asked.
- Think social feed first. The final launch was 27.5 seconds at 1080p/30 fps; future runtime follows the actual brief, usually short rather than expanded to a minute for convenience.
- Crator orange/ink/cream are available starting points, not a restriction against more interesting color.
- Suggested pastels: `#DEDEFF`, `#FFC5C6`, `#FFDAB6`, `#B7FFBA`. Ink near `#202323`; white/light grounds near `#fcfcfb`; warm offer stone `#F6F0E8`.
- Music should help shape rhythm early. The user liked the energy of the Softriver reference and selected Get Down by Rex Banner for this film. Source music again for a new brief; do not automatically reuse or claim a track license.
- If a voiceover is requested, Indian English is a recorded preference. Audition the actual lines against the picture; no voice or ElevenLabs preset has been permanently chosen.
- Sound effects were secondary and not added automatically. Follow the current brief for them.

## Historical facts, not reusable claims

The old film used a furniture business, inventory CSV, Dining Chair item, timber/components, a manufacturing manager and an approved work order. Oak-specific detail was rejected as distracting; furniture itself was accepted.

The hook compared Crator to Lovable for ERP. That comparison is useful only when it is true and understandable for the new audience. The film used “GPT-6 Astra” on the model control at the user's request. Neither becomes a permanent product claim.

The user confirmed a traditional implementation comparison of months and $10,000+, and Crator in weeks, for this film. Subscription figures were explicitly withdrawn from the video because of regional differences. Reconfirm pricing, implementation claims and CTA availability for new marketing work. Do not turn a historical approved number into an evergreen guarantee.

## Working style

Use the conversation and source material before asking the user to repeat context. Make concrete progress on authorized work. Show the actual moving result for motion feedback, acknowledge static sketches as such, and keep checkpoints so bold changes are reversible. User approval of a specific mechanism is evidence; older exploratory suggestions should not override later corrections.
